Для начала определимся с частью нашего проекта, который хотим переработать. 
Проект содержит часть фронта и эмуляцию бека, в нашем случае изменения касаются только фронта, поэтому бек оставляем без изменений.

Проект написан на едином стеке, знакомом всем командам, предпосылок к введению в проект новых фреймворков на данный момент и ближайшее будущее нет.

Команды знакомы с общей кодовой базой и возможность переиспользовать общие библиотеки при разделении монолитного фронтенда была бы кстати.
Как следствие, для нашего решения выбираем Webpack module federation. 
Не рассматриваем вопрос seo интеграции нашей платформы, поэтому ориентируется на runtime интеграцию и client-side композицию, которую предоставляет webpack.

Выделены микрофронтенды:

`main` - основной модуль проекта (host), содержит главную страницу, подключает остальные модули

`profile` - модуль регистрации и редактирования профиля. Поскольку требования к данным при регистрации профиля могут изменяться и тесно связаны с дальнейшим его редактированием, их разделение выглядит нецелесообразным.

`card` - модуль работы с карточками мест, включает ее создание, просмотр индивидуально и списком, управление лайками. На данном этапе выделение лайков в отдельный модуль выглядит нецелесообразным, поскольку данный функционал мал и связан с карточкой места (лайкаем именно ее). В дальнейшем возможно его отделение при усложнении логики.

`popup` - модуль, предоставляющий функциональность всплывающих форм. Возможно, может являться shared библиотекой.

`auth` - модуль, отвечающий за проверку необходимости логина пользователя и сам логин.

Модули структурированы следующим образом:

module-fm/<br>
├─ src/<br>
│  ├─ components/ - каталок с компонентами модуля (js скрипты)<br>
│  ├─ styles/ - каталог со стилями (css)<br>
│  ├─ resources/ - каталог с ресурсами (статика)<br>
│  ├─ utils/ - каталог с утилитами для api (js скрипты)<br>
